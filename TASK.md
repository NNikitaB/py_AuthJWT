```markdown
# Задание: Реализация Backend-приложения для Аутентификации и Авторизации

## Цель
Создание собственной системы аутентификации и авторизации. Приложение должно иметь уникальную логику доступа, не полагаясь только на встроенные функции фреймворков.

## Основные задачи
- Разработка схемы БД для управления доступом к ресурсам.
- Описание компонентов, определяющих доступ пользователя к ресурсам и действиям.

## Основные модули системы

### 1. Взаимодействие с пользователем
- **Регистрация**: Ввод имени, email, пароля и подтверждения пароля.
- **Обновление информации**: Редактирование профиля пользователя.
- **Удаление пользователя**: Мягкое удаление аккаунта (is_active=False), пользователь не может войти в систему.
- **Login**: Вход в систему по email и паролю.
- **Logout**: Выход из системы.
- **Идентификация**: Система должна идентифицировать пользователя после входа.

### 2. Система разграничения прав доступа
- **Описание структуры управления доступом**: В текстовом файле или README.md.
- **Создание таблиц в БД**: Реализация с тестовыми данными для демонстрации работы.
- **Обработка ошибок**:
  - 401 ошибка: Неопределенный пользователь.
  - 403 ошибка: Доступ запрещен для определенного пользователя.
- **API для администратора**: Возможность получения и изменения правил доступа.

### 3. Минимальные объекты бизнес-приложения
- Создание Mock-View для отображения потенциальных объектов или ошибок.
- Таблицы в БД создавать не требуется.

## Рекомендуемые технологии
- **DRF (Django Rest Framework)**
- **Postgres**
```


Ожидаемый результат:
* Готовое API с возможностью авторизации через Яндекс с последующей аутентификацией к запросам через внутренние токены API.
* Доступные эндпоинты: авторизация через яндекс, обновление внутреннего access_token; получение, изменение данных пользователя, удаление пользователя от имени суперпользователя; получение информации о аудио файлах пользователя: название файлов и путь в локальной хранилище.
* Документация по развертыванию сервиса и БД в Docker.
